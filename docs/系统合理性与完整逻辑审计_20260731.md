## 一、2026-07-31 总判断（修复前取证）

系统的总体方向是合理的，已经具备一个研究原型应有的主要工程骨架：边缘感知、本地临时决策、可靠上报、多边缘汇聚、轻量云融合、可选大模型复核、冲突协调、离线队列、最终结果回填和运行监测。事件信封、幂等、持久化汇聚及临时结果到最终结果的状态模型也符合分布式流处理的常见做法。

截至 2026-07-31，交通实现还没有形成完全闭合的科学论证。主要问题不在硬件，而在四处逻辑边界：

1. `risk.level` 当时同时承载交通状态、最危险节点、动作安全风险和模型让权依据，导致边缘 Qwen、证据上传和云复核被同一个值共同放大。
2. 文档称最终融合可异步，但在线多边缘事件当时仍被改写为 `cloud_sync` 并在边缘请求内执行 HTTP 上报，临时决策时延和云端接收时延没有真正解耦。
3. 2/4 节点超时汇聚当时也会生成最终结果，随后被标记为 `cloud_confirmed`；对于需要全局确认的动作，这个语义不安全。
4. 云端 ExtraTrees 和两两冲突消解能提高一致性，但没有显式交通控制目标函数，不能据此声称达到“全局最优”。

因此，准确表述应是：

> 当前系统是工程基础较完整、研究方向合理的云边协同原型；它已经能够证明分布式感知、可靠协同和一致性协调，但尚不能证明所有核心指标均已达标，也不能把现有冲突消解称为交通全局优化。

## 二、2026-07-31 代码中的真实完整流程（修复前取证）

当时实际流程为：

```text
场景原始输入
  → CloudEvents 风格事件信封与场景 Schema 校验
  → 场景 normalize() 生成统一 SemanticEvent
  → ASTGCN 交通感知与区域/节点状态计算
  → 场景本地规则和 Student 生成临时动作
  → defer gate 判断局部信息是否足够
  → selective 模式下可调用 Edge-Qwen
  → 公共调度器计算本地/同步云/异步云路径
  → 证据规划器决定摘要、特征或原始证据
  → 边缘上报并由云端按 sample_id、窗口和成员集合汇聚
  → ExtraTrees 进行轻量云融合
  → 必要时 Qwen 9B 结构化复核
  → 冲突检测和动作协调
  → provisional/final 记录、最终回填、监测和失败重试
```

这条链路本身完整，但“是否调用模型”“是否上传证据”“动作能否立即执行”必须被视为三条独立决策链，不能继续由一个风险等级同时控制。

建议明确拆成：

```text
模型路由：Student 是否足够？Edge-Qwen/云模型预计能否纠错？
证据路由：当前融合缺少什么信息？摘要、特征还是原始数据？
动作授权：该动作是否可逆、是否越权、是否需要完整节点确认？
```

## 三、逐模块合理性判断（判断对象为修复前版本）

| 模块 | 判断 | 依据与边界 |
| --- | --- | --- |
| CloudEvents 风格事件信封 | 合理 | `source + id` 去重、事件类型和数据内容解耦符合 [CloudEvents 规范](https://github.com/cloudevents/spec/blob/main/cloudevents/spec.md)。场景 `data` 可自定义，`dataschema` 是可选格式引用。 |
| 场景插件与统一 `SemanticEvent` | 合理 | 公共框架只约束统一语义，感知模型、风险、动作和融合由场景实现，符合通用框架与领域算法分离原则。 |
| ASTGCN 交通预测 | 合理 | ASTGCN 专门用于捕捉道路图的时空相关性，并在 PeMS 数据上验证；与当前交通场景匹配。[ASTGCN，AAAI 2019](https://ojs.aaai.org/index.php/AAAI/article/view/3881) |
| METIS 四分区 | 条件合理 | METIS 适合平衡图分区并减少割边，但固定四区和无重叠边界可能损失跨区依赖。必须单独报告边界节点误差，并与随机/地理分区对照。[METIS 多层图划分](https://www.maths.tcd.ie/~eoin/index/karypis.kumar_metis96.html) |
| FCM 风险标签 | 条件合理 | 流量、速度、占有率聚类可用于缺少人工标签时生成交通状态弱标签，FCM 也能表达状态边界模糊性；但它不是独立真值。若训练和测试都以同一聚类结果为标签，准确率只证明复现聚类规则，不能证明真实风险识别。 |
| Student 本地快速决策 | 合理 | 交通 Student 是场景专用低成本决策器，适合覆盖常见样本；公共框架不应要求所有场景都有 Student，只应要求场景提供本地决策和不确定性输出。 |
| defer gate | 条件合理 | “模型预测或让权给下游专家”的思路与 [Learning to Defer](https://proceedings.mlr.press/v119/mozannar20b.html) 一致，但应依据系统损失、下游纠错能力和成本训练，不能直接把业务风险当成模型一定无能。 |
| Edge-Qwen selective 路径 | 修复前不合理 | 当时选择条件包含 `event.risk.level >= medium`，而交通的该字段是区域风险和最危险节点风险的最大值，学校数据中几乎所有样本都会成为候选。它偏离了“只处理 Student 不确定样本”的原意。选择性分类应报告覆盖率—风险曲线，而不是先定高风险即调用。[Selective Classification](https://papers.neurips.cc/paper_files/paper/2017/hash/4a8423d5e91fda00bb7e46540e2b0cf1-Abstract.html) |
| Edge-Qwen 模型角色 | 条件合理 | 13～16 token 输入、单动作 token 输出使其更接近场景策略分类器，而非通用推理器。只要消融证明它在相同覆盖率/时延预算下优于 Student 或规则，这个角色成立；否则不应仅因它是大模型而保留在主路径。 |
| 公共网络与时延调度 | 条件合理 | 同时考虑 RTT、抖动、传输量、队列和计算时间，方向与云边协同推理中的动态划分一致；但固定 EWMA 权重和点估计不足以控制尾部时延，应增加预测误差区间和 P95/P99 预算。 |
| 每样本轻量摘要上云 | 合理 | 两个或多个边缘的整体信息只有汇聚端具备；正常联网下每样本持久化并上传小摘要合理。动态调度控制的应是是否等待最终结果、是否追加证据、是否调用大模型，而不是是否让云知道该样本。 |
| 在线摘要同步提交 | 修复前不合理 | 修复前的 `runtime.py` 把有汇聚规格的在线事件强制改成 `cloud_sync` 并在请求内执行云端 HTTP。现已改为普通摘要持久化后后台发送；只有业务动作明确要求完整云确认且时限允许时同步等待。 |
| SQLite 汇聚、幂等、超时部分汇聚 | 合理 | 持久状态、事件时间窗、重复过滤和迟到数据处理符合 [Dataflow 模型](https://research.google/pubs/the-dataflow-model-a-practical-approach-to-balancing-correctness-latency-and-cost-in-massive-scale-unbounded-out-of-order-data-processing/) 的正确性—时延—成本权衡。 |
| 2/4 超时汇聚后最终确认 | 修复前不合理 | 修复前允许达到最小成员数后完成部分汇聚，并把结果视为云确认。现已区分非权威 `partial_final` 与完整权威结果，部分信息不能授权需要完整全局确认的动作。 |
| ExtraTrees 轻量云融合 | 合理 | 对结构化风险、置信度、拓扑摘要做低时延融合符合正常路径要求，并且模型失败时有专业基线保底。需要独立时间切分验证，而不是只看训练集或伪标签一致率。 |
| Qwen 9B 云端复核 | 条件合理 | 仅用于少量分歧、复杂和解释事件，严格 JSON、动作白名单和失败回退是合理设计。它不适合进入 0.2 秒普通闭环，也不应直接绕过确定性安全检查执行动作。 |
| 冲突检测与两两消解 | 条件合理 | 能识别共享资源、动作互斥和参数偏差，足以支持“决策一致性协调”；但平均、裁剪和最多八轮两两处理没有网络级目标函数，不能证明全局最优。交通控制论文通常显式最小化总旅行时间/排队并满足约束。[VSL 与匝道控制 MPC](https://www.sciencedirect.com/science/article/pii/S0968090X05000264) |
| 本地安全动作白名单 | 合理 | 将高级决策器与受验证的保底控制、安全监视器分开，符合 [Simplex 安全架构](https://experts.illinois.edu/en/publications/the-simplex-architecture-for-safe-on-line-control-system-upgrades/)。安全策略的含义应是动作范围、变化率、资源权限和回退，不是“高风险就调用 Qwen”。 |
| Outbox、重试和幂等 | 合理 | 断网持久化、至少一次传输和接收端幂等是正确工程选择，能支持恢复后重放和最终修正。 |
| 同局域网边缘互助 | 缺少实现 | 当前公共框架中未发现真正的边缘到边缘摘要交换与局域网融合通道。现有可证明能力是各边缘单独自治、持久排队、恢复后云端复核。未实现前不能宣称“云断开时由两边直接融合”。 |
| 校准、ECE、覆盖率、PSI | 条件合理 | 神经网络置信度需要校准，[温度缩放](https://proceedings.mlr.press/v70/guo17a.html) 是合理起点；但 50 条固定分箱 ECE 波动大，PSI 只能说明分布变化而非准确率下降。时间序列还应采用按时间/路段分块的校准和置信区间。 |
| 学习式效用路由 | 合理但未验证 | 以纠错概率收益减去时延和字节成本，思想与 [RouteLLM](https://arxiv.org/abs/2406.18665) 一致；在真实反馈不足时保持 shadow 是正确做法，当前不能宣称已形成有效在线学习路由。 |
| 通用 0.8B 蒸馏 | 指标未满足 | `edge_llm/general_distillation.md` 已明确两轮候选没有通过发布门禁，最好版本三类宏平均仅保留 9B 的 69.17%，不能声称数学、代码、中文推理均达到 80%～90%。README 第 97 行“经过场景无关蒸馏”的发布描述与证据冲突。 |

## 四、最关键的因果问题

### 1. 四类含义必须拆开

当前交通插件计算：

```text
operational_risk_level = max(region_risk_level, max_node_risk_level)
event.risk.level = operational_risk_level
```

随后 Edge-Qwen 选择器和公共证据规划器又使用 `event.risk.level`。这样会形成错误因果链：

```text
某个节点风险较高
  → 整个分区事件被视为高风险
  → Edge-Qwen 被选中
  → 特征证据被要求
  → 云复核增加
  → 推理和排队抬高全链路时延
```

“业务后果严重”只能说明动作要更保守或需要更强确认，不能说明 Edge-Qwen 对这个样本一定比 Student 更准确。模型路由应基于预计纠错收益。

建议使用五个独立字段：

| 语义 | 用途 |
| --- | --- |
| `regional_state` | 正常、缓行、拥堵、严重拥堵，描述区域交通状态 |
| `operational_safety_risk` | 动作错误可能造成的后果，决定动作权限和确认级别 |
| `model_uncertainty` | Student/感知模型对当前判断是否可靠 |
| `escalation_expected_gain` | Edge-Qwen 或云模型预计能提高多少正确率/收益 |
| `evidence_completeness` | 当前摘要、特征、原始证据及成员是否齐全 |

### 2. Student、Edge-Qwen 和云端不是固定三级流水线

合理关系不是“所有事件 Student 后都跑 Qwen，再跑云”，而是：

```text
常见、明确样本：感知 → Student/规则 → 立即临时结果
少量边缘疑难样本：感知 → Student 不确定 → Edge-Qwen → 临时结果
每个在线样本：摘要进入持久队列并异步上云
普通云端事件：多边缘摘要 → ExtraTrees → 最终结果
少量复杂云端事件：分歧/证据不足/高纠错收益 → Qwen 9B → 最终修正
```

Edge-Qwen 是否保留在交通主路径，应由四组角色消融回答：规则、Student、Edge-Qwen、Student+选择性 Edge-Qwen。在相同覆盖率或相同平均时延预算下比较准确率、严重漏判率和动作收益。

### 3. 安全策略与模型选择必须分离

安全策略应由确定性代码执行，包括：

- 离线可执行动作白名单；
- 速度、匝道流率、分流比例的上下限；
- 相邻控制周期最大变化率；
- 动作所属路段/设备权限；
- 全局或不可逆动作必须满足的成员完整度与云确认；
- 模型超时、格式错误和冲突未消解时的保底动作。

高风险事件可以要求更完整的证据和更高确认等级，但不能因为高风险就无条件调用语言模型。

## 五、时延指标的客观判断

学校实测显示：Edge-Qwen 实际 HTTP 路径约 175～191 ms；非 Qwen 的 `cloud_async` 均值约 227.9 ms；Qwen 路径和同步最终闭环更长。当前完整云融合最终结果无法稳定满足 0.2 秒，这是测量事实，不应通过更改指标名称掩盖。

系统应同时报告四个口径：

1. 本地临时结果时延：输入到 `provisional` 可用；
2. 云端接收时延：摘要进入云端持久存储；
3. 轻量融合最终时延：预期成员汇聚并生成 `final`；
4. 大模型修正时延：复杂事件经 Edge-Qwen 或 Qwen 9B 后完成。

若普通监测业务允许先用临时结果、不阻塞等待云端，那么第 1 项可以作为实时业务响应；但报告必须同时给出第 3 项，且不能把“临时响应小于 0.2 秒”写成“全局最终闭环小于 0.2 秒”。需要停机、区域分流等不可逆动作时，必须等待满足策略的最终确认，目前不能保证 0.2 秒。

本周最现实的时延整改是：本地临时结果生成后立即返回；摘要与本地结果以同一事务写入 Outbox；后台发送器每样本异步上报；云端最终结果回推修正。Qwen 9B 永远不进入普通 0.2 秒主路径。

## 六、交通“全局决策”的合理边界

当前系统在云端做了两件有价值的事：

- 融合相邻区域和多个边缘的状态，纠正单边缘局部判断；
- 检测对同一共享资源的冲突动作，并进行裁剪或协调。

这些足以称为“全局信息融合”和“全局一致性协调”。但论文中的交通全局优化通常需要：

```text
明确状态转移/仿真模型
+ 明确目标（总旅行时间、排队长度、吞吐、风险）
+ 动作和安全约束
+ 对照局部控制、集中式 MPC 或分布式 MPC
```

[全局与局部 MPC 对照研究](https://doi.org/10.1109/TITS.2012.2195493) 也说明局部方法通常是次优的，而集中式方案存在实时计算难题。你现在的系统可以把云端协调器作为研究贡献，但若要使用“全局优化”字样，应在 SUMO 或其他交通仿真中加入总旅行时间、平均速度、排队长度和吞吐收益，并至少与无控制、局部规则和一个 MPC/协调控制基准比较。

## 七、风险标签与评估是否科学

使用 FCM 对速度、流量、占有率聚类生成四类交通状态，在没有人工风险标签的条件下是合理的弱监督方案。问题在于证据等级：

- FCM 标签可用于训练和开发；
- 不能把对同一 FCM 标签的复现准确率当成真实交通风险正确率；
- 最终测试集应按时间和路段隔离，防止相邻时间窗泄漏；
- 最好增加独立真值，如后续 5～15 分钟拥堵持续/传播、速度跌破物理阈值、人工抽检或仿真状态；
- 聚类中心和阈值只能在训练期确定，不能用测试分布重新拟合。

时间序列不满足普通随机交换性的情况很常见，因此 conformal 风险集合也应采用时间感知校准，而不是随机打散。相关工作明确把时间序列依赖作为单独问题处理：[Conformal Time-Series Forecasting](https://papers.neurips.cc/paper/2021/file/312f1ba2a72318edaaa995a67835fad5-Paper.pdf)。

## 八、当前可以成立与不能成立的表述

### 可以成立

- 建成了场景插件化的分布式云边协同框架；
- 边缘可独立感知并产生本地临时决策；
- 正常联网时每样本可上报轻量摘要，云端完成多边缘关联与融合；
- 支持幂等、断网排队、恢复补传、超时部分汇聚和最终结果修正；
- 交通场景采用 ASTGCN、图分区、Student/Edge-Qwen 选择性决策和云端轻量融合；
- 云端能进行共享资源冲突检测和一致性协调；
- Edge-Qwen 内存满足 1.5 GB 限制，单模型推理可在 Orin Nano 上运行。

### 目前不能成立

- 所有数学、代码、自然语言能力均保留 9B 的 80%～90%；
- 完整多边缘最终闭环平均稳定小于 0.2 秒；
- 当前 Edge-Qwen 调用率由合理风险策略自动得到；
- 2/4 部分汇聚等同于完整云确认；
- 两两冲突消解已经实现交通全局最优；
- 云断开时两个边缘会自动在局域网交换摘要并融合；
- FCM 伪标签上的准确率等同于真实风险识别准确率；
- 学习式效用路由已经在线验证有效。

## 十一、最终结论

系统不是推倒重来型问题。公共框架的可靠传输、汇聚、幂等、插件契约、监测和临时到最终状态管理都有保留价值；ASTGCN、场景 Student、轻量云融合和可选大模型也都有合理位置。

真正需要收敛的是语义和主路径：

```text
本地快速决策负责实时性
每样本摘要异步上云负责全局可见性
轻量融合负责正常最终结果
Edge-Qwen/9B 只对有预计纠错收益的少量事件增强
确定性安全策略负责动作授权
完整度与业务策略决定是否允许等待或执行
```

按这条逻辑修改后，系统可以成为结构清楚、可解释、可做消融并能诚实报告边界的参赛原型。当前最紧迫的不是再提高 Jetson 并发或继续调 Qwen 阈值，而是先修正风险语义、同步路径和部分汇聚确认；否则硬件优化只会掩盖错误触发和错误计时，无法让系统真正收敛。
