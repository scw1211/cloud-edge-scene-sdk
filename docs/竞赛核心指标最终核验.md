## 正式双场景端到端

### 工业

正式主样本为 90 组 RGB/红外、共 180 个受控 score 事件：

- 本地成功率、规则准确率、authoritative-final rate 均为 100%。
- Qwen 选择 60/180，完成 60/60，规则一致率 100%。
- score-input -> provisional 平均 111.077345 ms。
- 该报告明确记录 `perception_model_executed=false`：仓库没有可运行的工业视觉权重和带标注视觉测试集，
  因此不能将 111.077 ms 表述为“原始图像 -> 决策”的完整视觉 E2E。
- selected-only Qwen 平均 206.446 ms，不是 180 个事件的总体 E2E；总体摊销 Qwen 延迟为 68.815 ms。
- Nano 时钟落后云端约 779 天，跨机 `cloud_receipt_latency` 无效；边缘本地单调时钟测得的 provisional 延迟仍有效。

### 交通

正式固定连续 test[100:200]，100 个窗口、4 个 METIS 分区，共 400 个边缘事件：

- 400/400 路由成功，100/100 聚合完整，HTTP 持久连接重连 0。
- event business completion 平均 174.240621 ms，满足 200 ms 主门；86% 的事件低于 200 ms。
- 每个窗口等待最慢分区的 sample business completion 平均 212.514133 ms，未满足更严格的 200 ms 窗口门。
- Qwen 被选择 30 次但接受 0 次，30 次均因 `authorized_candidate_action_missing` 安全回退；没有 runtime error。
- 当前连续窗自然冲突率为 0，因此 `conflict_resolution_evaluated=false`，不能用 0 冲突证明解决率。

## 弱网与并发复核

当前静态 Q5 使用真实故障代理完成了 mild、severe、outage 注入并恢复；代理原始日志共有
1,302 行。按 profile 统计：

| Profile | 请求 | 数据面 | 丢弃 | 延迟注入 | 后端错误 |
|---|---:|---:|---:|---:|---:|
| mild | 67 | 56 | 0 | 66 | 0 |
| severe | 54 | 44 | 3 | 53 | 0 |
| outage | 12 | 9 | 11 | 0 | 0 |
| normal | 1,169 | 666 | 0 | 0 | 0 |

完整矩阵两次都在 concurrency=8 阶段发生边缘 HTTP 503/connection reset，脚本 fail-fast，故未生成完整最终 JSON。
失败时边缘和 llama-server 均保持 active、NRestarts=0、无 OOM，恢复后 Outbox/reconciliation/durable 均为 0。
这应作为当前的并发上限缺口，而不是弱网功能保持率通过证据。

可单独引用的历史交通弱网基线为：normal/mild/severe/outage 业务可用率均 100%，
自适应 severe 平均 56.871 ms（比固定同步降低 69.19%），outage 平均 54.125 ms（降低 82.42%）。
由于不是当前静态 Q5 release，不与当前模型身份混写。

## 提交材料表述边界

1. 内存写“静态 Q5 进程严格观测峰值 1.047 GB”，不要写模型文件大小等同运行内存。
2. 工业写“受控 RGB/红外 score 事件 -> 决策”，不要写成已实测原始图像视觉网络。
3. 时延主表同时列事件均值和更严格的窗口均值；不要只列较好的一项。
4. 跨机时延在 Nano 时钟修复前全部排除，只使用同机单调时钟口径。
5. 通用能力、代码能力和同协议 TTFT 暂列缺口，不引用旧候选或异协议数字冒充通过。
6. 当前 concurrency=8 是已知失败边界；演示并发保持 4 组以内，或先实现请求背压/排队再复测。
