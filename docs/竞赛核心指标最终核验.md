## 当前静态 Q5 核心实测

### Nano222 500 次严格交替

- 总请求：500/500；交通 250，工业 250，严格交替且无串场。
- 平均推理时延：132.610802 ms。
- 交通 accuracy 72.8%，weighted-F1 73.6485551%。
- 工业 accuracy / macro-F1 / weighted-F1 均为 100%。
- 合法输出率 100%，17 -> 1 token 合同 100%。
- 严格内存峰值：1,047,126,016 bytes，定义为
  `max(VmHWM, 20 ms 采样的 VmRSS + VmSwap)`，不扣基线。
- request 100 -> 500 的 RSS+swap 增长：999,424 bytes。
- 最低 MemAvailable：1,573,306,368 bytes；OOM 增量 0；推理阶段 D 状态 0。
- 注意：这是高频观测门，不是独立 cgroup 的硬上限执行。

### 本机完整质量集

- 交通 2,400 条：accuracy 68.3333333%，weighted-F1 69.0415445%。
- 工业 960 条：accuracy / macro-F1 / weighted-F1 均为 100%。
- 两场景合法输出率 100%，17 -> 1 token，运行时 `/lora-adapters=[]`。

### TTFT 复测与内存约束

- Nano222 正式 16/16 batch 配置的 500 次严格交替完整请求均值为 132.610802 ms；
  直接调用正式 18190 时，冷请求为 228.979 ms，预热后连续请求约 128.3--133.6 ms。
- 为核对旧证据中的约 80 ms，实测将唯一运行变量改为 batch/ubatch 32/32：500 次均值
  降至 88.176952 ms，P95 为 91.211311 ms，工业三项仍为 100%，交通 accuracy 为 72.0%。
- 但 32/32 的严格内存峰值升至 1,615,671,296 bytes，超过 1.5 GB 门 115,671,296 bytes；
  因此该优化门禁失败并已回滚，正式服务继续使用 16/16。不能只报 88.18 ms 而隐去内存失败。
- 同一个 Ollama 0.31.1 / 同一 GPU / 同一组 80 条 17-token、单输出 token 请求，
  9B 均值 249.376793 ms、静态 Q5 均值 184.261588 ms，TTFT 降幅 26.111173%。
- 同一静态 Q5、同一 Ollama 将 17-token 输入与旧 725--733 token 原始 JSON 对比，
  均值为 175.283617 / 227.170730 ms，降幅 22.840580%。两种当前开发口径都没有达到 75%。
- 旧 Q6 的 82.62 ms 和 93.6931% 降幅绑定旧模型、13-token 输入及不同 runtime 参数，
  只能作为历史优化背景，不能代替当前静态 Q5 的门禁。

### 当前静态 Q5 通用能力开发门

- 使用同一 80 题开发集和完整 Qwen3.5 非思考模板：教师 9B 宏观得分 66.6667%，
  静态 Q5 为 40.0%，宏观保持率 60.0%。
- 分项保持率：代码 `20.0% / 60.0% = 33.33%`；数学
  `56.6667% / 70.0% = 80.95%`；自然语言推理
  `43.3333% / 70.0% = 61.90%`。
- 该结果来自未提交工作树上的开发复测，不是正式盲测；但它已经足以判定当前模型没有达到
  80%--90% 通用能力保持门，不能继续引用旧模型结果淡化缺口。

## 提交材料表述边界

1. 内存写“静态 Q5 进程严格观测峰值 1.047 GB”，不要写模型文件大小等同运行内存。
2. 工业要分开写：116 张图像是真实视觉质量/TensorRT 推理门，2 个事件是真实图像云边闭环 smoke，
   180 事件是 score-input 弱网/冲突/并发矩阵；三者不得互相扩大分母或测量起点。
3. 时延主表同时列事件均值和更严格的窗口均值；不要只列较好的一项。
4. 跨机时延在 Nano 时钟修复前全部排除，只使用同机单调时钟口径。
5. 通用能力和 TTFT 75% 均按当前开发复测列为失败；不引用旧候选、不同模型或异协议数字冒充通过。
6. 并发 8 已不再发生连接重置；但单 slot Qwen 在并发 4/8 会触发部分超时并走安全回退，演示时应如实区分“业务成功”与“Qwen 完成”。
