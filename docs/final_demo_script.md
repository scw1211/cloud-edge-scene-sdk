# 最终答辩演示脚本

建议用8分钟完成演示，先讲结果，再展开证据边界。

## 0:00-0:40 开场

> 作品在统一云边框架中部署了交通四区域和工业十产品双模态两类差异明显的场景。边缘先形成即时结果，需要协同时只上送紧凑证据；云端进行跨节点汇总与综合判断，弱网恢复后由Outbox补传。

## 0:40-2:10 工业演示

打开“系统演示”，选择“工业双模态”，依次点击四阶段：

1. 同一工件的RGB和红外输入；
2. 两个边缘节点分别完成专业感知并形成即时结果；
3. 云端收齐两路摘要，由冻结resolver形成单一工件级综合判断；
4. 两路记录回填一致的最终业务结果。

同时说明：Qwen3.5-9B只提供低频异步辅助审计意见，不阻塞工业业务结果，也不直接替代冻结resolver。

## 2:10-3:20 交通演示

切换“智慧交通”，说明四区域时序与状态在边缘形成局部态势，CollaborationScheduler按任务和网络状态选择实际路径，云端汇总四区紧凑摘要，输出全局风险、重点区域和协调建议。正式主链不宣称自动交通控制收益。

## 常见追问

- 为什么工业阈值结果不直接上线？443条标签全部参与选参，不是held-out或生产验证，所以固定标记`DEVELOPMENT_DEMO_ONLY`。
- 9B为什么不阻塞工业？工业要求确定性、低时延；冻结resolver负责结构化综合判断，9B意见异步记录。
- 101.497 ms是不是同一批实验？不是。交通是全Qwen primary的400个单节点事件正式运行，工业是从prepared NCHW开始的感知E2E与业务链两个冻结实测分布的组件组合。加权均值的赛题门裁决为PASS，同时单列测量边界并不报总体P95。
- 为什么安全响应降低71.545%还会有185次修订？这个指标衡量符合权限门的响应可用时间，不是提前获得权威终态。局部信息可以先返回，需要云确认的动作仍被延后，权威结果随后以更高revision回填。
- 能否扩展？工业覆盖10产品×2模态；交通完成4→3节点配对实验，两臂100%完成，存活事件风险/动作/路由100%一致，吞吐+52.94%，代价是覆盖保留75%。更大规模和未见产品仍是后续边界。
