# 最终规则路由与可靠性架构

## 在线主链

最终运行时只有 `CollaborationScheduler` 负责业务路径选择。输入先由场景插件形成边缘即时结果和风险信息，再由调度器根据任务风险、云端可用性、网络状态、剩余时限及业务约束，从以下三条实际路径中确定一条：

```text
场景输入
  → 专业感知与边缘即时结果
  → CollaborationScheduler
      ├─ edge_only：本地完成
      ├─ cloud_async：先返回边缘结果，云端结果后续修订
      └─ cloud_sync：等待云端综合判断后完成
  → 可靠交付、版本检查与结果回填
```

系统由单一 `CollaborationScheduler` 按冻结规则选择处理路径，不存在旁路接管、候选策略二次改写路径或多层策略投票。

## 执行降级

`local_autonomy` 是云端不可用或云路径执行失败后的执行状态，不是独立的路径选择器。发生网络中断时，边缘继续提供能够安全完成的基本业务；需要上送的数据进入持久化队列，网络恢复后补传。事件ID、幂等记录、结果版本和过期检查共同防止重复处理及旧结果覆盖新状态。

## 云端职责

- 工业场景：汇聚RGB与红外结果，形成工件级综合判断；ExtraTrees候选仅在冻结证据声明的shadow边界内使用。9B只做低频异步辅助审计，不阻塞工业业务结果。
- 交通场景：汇聚多区域摘要并提供全局分析或后续周期建议；当前周期的边缘业务不等待迟到的跨区域控制结果。

## 责任边界

| 环节 | 唯一责任模块 |
|---|---|
| 场景语义、风险与本地动作 | 工业或交通场景插件 |
| `edge_only` / `cloud_async` / `cloud_sync` 路径选择 | `CollaborationScheduler` |
| 云路径失败后的本地继续运行 | 执行降级逻辑 |
| 断网缓存、重试与幂等 | 可靠传输组件 |
| 多节点聚合与最终结果版本 | 云端聚合和结果回填组件 |

最终部署配置、答辩页面和评分证据均以这条规则主链为准。
