# 本机真实交通系统实测

2026 年 7 月 29 日已完成三类真实权重测试：

1. 原工程完整链路；
2. 生成后的独立 SDK 完整链路；
3. 云端 Qwen3.5 9B 异常增强链路。

三类测试都实际加载了 PEMS08 推理数组、联合 ASTGCN checkpoint、交通
Student、defer gate、特征编码器、Edge-Qwen 0.8B Q6 和云端 ExtraTrees。
第三类额外调用了 Ollama 中的 `qwen3.5:9b`。无权重规则冒烟未计入结果。

## 完整性结果

| 指标 | 原工程 | 独立 SDK |
| --- | ---: | ---: |
| 请求成功率 | 100% | 100% |
| Edge-Qwen 实际选择/接受 | 4/4 | 4/4 |
| 四分区完整汇聚率 | 100% | 100% |
| 云端收到成员 | 4/4 | 4/4 |

| 残余冲突 | 0 | 0 |

独立 SDK 的通过说明交通系统不再依赖原 ASTGCN 工程中的隐式 Python 模块或
绝对模型路径。

## 时延结果

| 指标 | 结果 |
| --- | ---: |
| ASTGCN 常驻感知 | 10.30–12.51 ms |
| Edge-Qwen 被选择后的平均推理 | 45.42–46.29 ms |
| 单机四逻辑边竞争时外部平均闭环 | 343.34–348.87 ms |
| 单机竞争时 0.2 s 达标率 | 25% |
| 原工程 provisional→final 平均 | 837.0 ms |

本机完整测试故意并发提交四个区域，但四个逻辑边共享同一个
`parallel=1` llama-server。后三个请求会等待同一 Edge-Qwen 槽，因此这项
343–349 ms 是单机竞争压力，不是两台 Jetson 的分布式指标。先前的无竞争
单边完整请求为 118–171 ms，但正式报告仍应使用实验室两台 Jetson 的重复实测。

## Qwen 9B 路径

四个 ExtraTrees 结果均被真实 Qwen3.5 9B 结构化复核并接受。常驻四次复核为
1188.51、1209.23、1380.74 和 1262.46 ms，平均 1260.23 ms；完整四边异常
增强组耗时 5573.10 ms。

结论是 9B 只能处理少量高风险、分歧或解释事件，并以异步方式回填。它不能进入
常态 0.2 s 主路径，也不能把这项时延与 ExtraTrees 轻量融合混为一谈。

## 实验室必须补测

- 两台 Jetson 各运行一个独立 Edge-Qwen 时的四分区并发到达偏差；
- provisional 时延、最终回填时延、P50/P95/P99；
- Jetson 实际内存、TTFT 和连续运行温度/功耗；
- 云断开、局域网保留以及边缘完全隔离三种故障；
- 网络恢复后的队列补传、最终修正率和业务保持率。
